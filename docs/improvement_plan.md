# 数据分析页面改进方案

> 仓库：`git@github.com:2220258345/ds-pc28.git`
> 关联文档：[strategy_exploration_report.md](./strategy_exploration_report.md)

## 1. 背景与目标

当前前端看板（`static/index.html`）在「实时展示」与「下钻交互」上已经可用，但从「帮助人类做数据分析」的角度看，存在三类问题：

1. **统计口径不规范，且可能误导**：把“遗漏/未出”当作决策信号，但缺少“随机独立、不可预测”的风险提示；部分“冷热”标签语义反了。
2. **关键分析维度缺失**：没有和值分布、形态频率、连号统计等与理论分布对比的基础视图。
3. **体验与工程化不足**：历史列表无日期/搜索、头部状态是死的、走势图无交互、单文件过大且存在重复逻辑。

本方案的目标是：在保持现有实时能力不回退的前提下，把页面从「看盘面板」升级为「有统计依据、有风险提示、可进一步分析」的数据分析工具。

## 2. 改进原则

- **正确性优先**：任何“冷热/遗漏”结论必须基于真实概率或历史分位，不能用拍脑袋阈值。
- **风险透明**：所有策略/遗漏类展示都必须显著标注“随机独立、无预测优势”。
- **可分析性**：新增视图必须能和理论值对比，而不是只展示原始数字。
- **可维护性**：优先消除前后端重复逻辑，保持单一数据源。
- **不回退**：SSE、倒计时、区间下钻、移动端适配等现有能力保持可用。

## 3. 改进项清单

### P0 — 正确性与风险（必须先做）

| 编号 | 问题 | 目标 | 方案 | 涉及文件 |
|------|------|------|------|----------|
| P0-1 | “未开/冷热”语义混乱，`warm` 被标成“偏热” | 术语一致：久未出现=“冷”，并加免责提示 | 后端状态标签统一为 `正常/偏冷/冷/极冷`；前端顶部加“开奖为独立随机事件，遗漏不代表更易/更难出现”横幅 | `app/core/db.py`（或 `app/storage/store.py`）、`static/index.html` |
| P0-2 | 后端已算 `med/p95/p99/ratio`，前端只显示 `avg/max` | 展示当前遗漏的历史分位 | 未开卡片增加“中位数 / P95 / P99 / 当前分位”，让用户知道“现在多久没出，在历史里排多前” | `static/index.html` |
| P0-3 | 特码未出用 `odds*1.2` 当理论周期 | 用真实概率计算理论间隔 | 由后端返回每个和值的真实概率（3d10 组合数/1000）与理论平均间隔，前端据此判定，删除 `odds*1.2` 近似 | `app/storage/store.py`（或 `core/db.py`）、`static/index.html` |
| P0-4 | E9 回测显著展示历史盈利，但无风险提示 | 用户不被 +110K 误导 | 回测摘要区加显著提示并链接研究报告：“历史样本噪声，无预测优势，近期效应已衰减” | `static/index.html` |

### P1 — 分析维度（核心价值）

| 编号 | 问题 | 方案 | 说明 |
|------|------|------|------|
| P1-1 | 无和值分布 | 新增「和值分布」图：经验频次柱状图 + 理论 3d10 概率曲线叠加 | 直接暴露数据是否偏离理论 |
| P1-2 | 无形态频率对比 | 新增「大小/单双/组合」频率表：经验占比 vs 理论占比（大/双各 50%，大双/小单 26.9%，大单/小双 23.1%） | 用简单表格即可，价值高 |
| P1-3 | 无连号分析 | 新增「连号长度分布」：大小、单双、组合各自连出 1~N 期的频次 | 展示常见“连庄”现象的实际分布 |
| P1-4 | 历史列表无日期、无搜索 | 列表加 `draw_date` 列；顶部加“期号/日期”搜索框与页码跳转 | 复用现有 `jumpToHistory` 逻辑 |
| P1-5 | 无法导出 | 当前筛选区间/统计结果支持“复制 CSV / 下载” | 便于继续用 Excel/Python 分析 |

### P2 — 体验与工程化

| 编号 | 问题 | 方案 |
|------|------|------|
| P2-1 | 走势图为静态 SVG | 改用现有 ECharts，加入 tooltip、缩放、悬停；移除手写 SVG |
| P2-2 | 头部“自动采集中”硬编码、`dbInfo` 永远“加载中” | 头部接入 `/api/status`，显示总期数、最新期号、最后更新时间、采集器状态 |
| P2-3 | 单文件 2482 行、回测逻辑重复 | 拆分 `static/css/`、`static/js/`；回测只用后端 `/api/backtest`，删除前端/`generate_chart.py` 里的重复 JS 引擎 |
| P2-4 | 颜色依赖强 | 关键状态同时用文字标签，保证色盲可读 |

## 4. 关联后端改进（顺带清理）

以下不属于页面，但与“整体质量”相关，建议纳入后续清理：

- 统一维护时段口径（`time_sync.py`、`db.py`、`backtest_e9.py` 三处不一致：30/33 分钟、是否区分冬夏令）。
- TLS 校验默认开启，旧源用显式开关降级；公网部署增加可选鉴权。
- 补充接口级回归测试（`/api/status`、`/api/backtest`、`/api/unopened-v2` 的 golden 断言）。

## 5. 分阶段实施

| 阶段 | 内容 | 预计 |
|------|------|------|
| Phase 1 | P0 全部（正确性 + 风险提示 + 分位展示 + 真实概率） | 0.5~1 天 |
| Phase 2 | P1 全部（分布/频率/连号 + 历史搜索 + 导出） | 2~3 天 |
| Phase 3 | P2 全部（走势交互、头部状态、模块化、无障碍） | 1~2 天 |

## 6. 验收标准

- 页面显著位置有“随机独立、无预测优势”提示。
- 遗漏状态语义一致，且能显示当前遗漏的历史分位（P95/P99）。
- 特码未出不再使用 `odds*1.2`，改用真实概率/理论间隔。
- 新增和值分布、形态频率、连号长度视图，均与理论值对比。
- 历史列表可显示日期、可按期号/日期搜索、可跳页。
- 头部显示真实数据同步状态与最后更新时间。
- E9 回测区域有风险提示并链接研究报告。

## 7. 风险与依赖

- 新增统计视图需要额外聚合接口；数据量仅约 3.2 万期，可在后端一次性聚合返回，避免前端重复计算。
- 前端拆分模块时注意保留 SSE、倒计时、区间下钻、移动端适配等既有能力。
- 维护时段口径统一会影响回测与统计结果，需先明确业务正确值再改，并用回归测试兜底。
